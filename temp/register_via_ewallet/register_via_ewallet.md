# Register via E-Wallet — Implementation Plan

> **Status:** Pending review  
> **Goal:** Allow any logged-in user (admin or member) to register a new member account by paying the package entry fee directly from their e-wallet, bypassing the registration code system. Non-withdrawable funds are spent first.

---

## 1. Core Concept

Currently, registration requires a **registration code** (pre-generated by admin). This plan adds an alternative path:

| Method | Input | Source of Payment |
|--------|-------|-------------------|
| **Registration Code** (existing) | Enter 12-char code | Code was pre-purchased |
| **E-Wallet** (new) | Select package | Debited from payer's e-wallet in real-time |

> **Who pays:** The logged-in user (admin or member) who fills out the registration form. Their e-wallet is debited by the selected package's `entry_fee`.

> **Who receives commissions:** Same as code registration — pairing, direct referral, indirect referral all fire immediately upon successful registration.

## 2. Database Changes

### 2.1 Make `reg_code_id` Nullable

Currently `users.reg_code_id` is required (NOT NULL implied by the INSERT). E-wallet registrations have no code.

```sql
ALTER TABLE users
  MODIFY COLUMN reg_code_id INT UNSIGNED NULL;
```

> **Note:** Check if `reg_code_id` already allows NULL. If the current schema has it as `NULL`, no change needed.

### 2.2 Track Registration Payment Method

Add a column to distinguish how the account was registered:

```sql
ALTER TABLE users
  ADD COLUMN reg_payment_method ENUM('code','ewallet') NOT NULL DEFAULT 'code'
  AFTER reg_code_id;
```

### 2.3 Track Who Paid (for E-Wallet Registrations)

Add a column to record which user paid the entry fee:

```sql

  AFTER reg_payment_method;
```

## 3. Business Logic

### 3.1 `User::registerViaEwallet()` — New Method

**File:** `models/User.php`

```php
/**
 * Register a new member using e-wallet payment.
 *
 * @param int    $payerId    User ID of the person paying (admin or member)
 * @param array  $data       Same as register() + 'package_id'
 * @return int   New member ID
 * @throws RuntimeException on failure
 */
public static function registerViaEwallet(int $payerId, array $data): int
{
    $pdo = db();

    // Fetch package entry fee
    $pkg = Package::find((int)$data['package_id']);
    if (!$pkg) {
        throw new RuntimeException('Package not found.');
    }
    $entryFee = (float) $pkg['entry_fee'];

    // Debit payer's e-wallet (non-withdrawable first)
    $debitOk = Ewallet::debitInternal(
        $payerId,
        $entryFee,
        0, // ref_id will be updated after user creation
        'registration',
        'Registration fee for @' . $data['username']
    );
    if (!$debitOk) {
        throw new RuntimeException('Insufficient e-wallet balance to cover registration fee.');
    }

    $pdo->beginTransaction();
    try {
        // Verify binary slot is free
        $slotCheck = $pdo->prepare("
            SELECT COUNT(*) FROM users
            WHERE binary_parent_id = ? AND binary_position = ?
        ");
        $slotCheck->execute([$data['binary_parent_id'], $data['binary_position']]);
        if ((int)$slotCheck->fetchColumn() > 0) {
            throw new RuntimeException('That binary position is already taken.');
        }

        // Insert the new member (reg_code_id = NULL, reg_payment_method = 'ewallet')
        $hash = password_hash($data['password'], PASSWORD_BCRYPT, ['cost' => 12);
        $pdo->prepare("
            INSERT INTO users
              (username, password_hash, package_id, reg_code_id,
               reg_payment_method, reg_paid_by,
               sponsor_id, binary_parent_id, binary_position)
            VALUES (?, ?, ?, NULL, 'ewallet', ?, ?, ?, ?)
        ")->execute([
            $data['username'],
            $hash,
            $data['package_id'],
            $payerId,
            $data['sponsor_id'],
            $data['binary_parent_id'],
            $data['binary_position'],
        ]);
        $newId = (int)$pdo->lastInsertId();

        $pdo->commit();
    } catch (\Exception $e) {
        $pdo->rollBack();
        throw $e;
    }

    // ── Real-time commissions (same as code registration) ──
    Commission::processBinaryPlacement($newId, $data['binary_parent_id'], $data['binary_position']);
    Commission::processDirectReferral($data['sponsor_id'], $newId, $data['package_id']);
    Commission::processIndirectReferral($data['sponsor_id'], $newId, $data['package_id']);

    return $newId;
}
```

> **Ledger entry:** `Ewallet::debitInternal()` already records the debit in `ewallet_ledger` with `ref_type = 'registration'`.

### 5.2 `AuthController::doRegister()` — Branch by Payment Method

```php
public function doRegister(): void
{
    csrf_verify();

    $paymentMethod = $_POST['payment_method'] ?? 'code'; // 'code' or 'ewallet'
    $username      = strtolower(trim($_POST['username']         ?? ''));
    $password      = $_POST['password']                          ?? '';
    $passwordC     = $_POST['password_confirm']                  ?? '';
    $sponsorU      = strtolower(trim($_POST['sponsor_username'] ?? ''));
    $uplineU       = strtolower(trim($_POST['upline_username']  ?? ''));
    $position      = $_POST['binary_position']                   ?? '';

    // ── Common validation ──
    if (!is_valid_username($username)) { ... }
    if (User::usernameExists($username)) { ... }
    if ($password !== $passwordC || strlen($password) < 8) { ... }

    // Resolve sponsor & upline IDs
    $sponsor = User::findByUsername($sponsorU);
    $upline  = User::findByUsername($uplineU);
    if (!$sponsor) { flash('error', 'Sponsor not found.'); redirect('/?page=register'); }
    if (!$upline)  { flash('error', 'Upline not found.'); redirect('/?page=register'); }

    // ── CODE PATH ──
    if ($paymentMethod === 'code') {
        $code = strtoupper(trim($_POST['reg_code'] ?? ''));
        $codeRow = Code::validate($code);
        if (!$codeRow) { flash('error', 'Invalid or already-used registration code.'); redirect('/?page=register'); }

        $newId = User::register([
            'username'         => $username,
            'password'         => $password,
            'package_id'       => (int)$codeRow['package_id'],
            'reg_code_id'      => (int)$codeRow['id'],
            'sponsor_id'       => (int)$sponsor['id'],
            'binary_parent_id' => (int)$upline['id'],
            'binary_position'  => $position,
        ]);

        flash('success', 'Account created successfully! Welcome, @' . $username);
        redirect('/?page=register');
        return;
    }

    // ── E-WALLET PATH ──
    $packageId = (int)($_POST['package_id'] ?? 0);
    if ($packageId <= 0) {
        flash('error', 'Please select a package.');
        redirect('/?page=register');
        return;
    }

    $pkg = Package::find($packageId);
    if (!$pkg || $pkg['status'] !== 'active') {
        flash('error', 'Invalid package selected.');
        redirect('/?page=register');
        return;
    }

    // Must be logged in to pay with e-wallet
    if (!Auth::check()) {
        flash('error', 'Please log in to register with e-wallet.');
        redirect('/?page=login');
        return;
    }

    $payerId = Auth::id();
    try {
        $newId = User::registerViaEwallet($payerId, [
            'username'         => $username,
            'password'         => $password,
            'package_id'       => $packageId,
            'sponsor_id'       => (int)$sponsor['id'],
            'binary_parent_id' => (int)$upline['id'],
            'binary_position'  => $position,
        ]);

        flash('success', 'Account created successfully! ₱' . number_format($pkg['entry_fee'], 2) . ' debited from your e-wallet.');
    } catch (RuntimeException $e) {
        flash('error', $e->getMessage());
    }

    redirect('/?page=register');
}
```

## 9. QA Test Plan (Brief)

1. **Code registration** (existing flow) still works unchanged.
2. **E-wallet registration with 1 package** — auto-selected, no dropdown.
3. **E-wallet registration with 2+ packages** — dropdown appears, fee updates on selection.
4. **Insufficient balance** — error flash, no user created, no balance debited.
5. **Sufficient balance** — user created, payer's `ewallet_balance` and `withdrawable_balance` reduced by entry fee (non-withdrawable first).
6. **Ledger entry** — payer sees "Registration fee for @newmember" in earnings ledger.
7. **Commissions fire** — sponsor gets direct referral, ancestors get pairing bonuses.
8. **Admin user view** — shows "💰 E-Wallet" with payer username.
9. **Guest tries e-wallet** — redirected to login with error.
10. **Member pays for registration** — same flow as admin, works correctly.

## Open Questions for Review

1. **Should the entry fee go to a system/admin account?** Currently it is simply burned (debited from payer, no credit to anyone). Alternative: credit to admin e-wallet as "registration revenue".
2. **Should we track registration payments in a new table** (e.g., `registration_payments`) for audit, or is the `ewallet_ledger` entry sufficient?
3. **Should guests be allowed to register via e-wallet?** Current plan says no (must be logged in). If yes, we'd need a guest checkout flow.
